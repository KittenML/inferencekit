# Optional plans and existing approvals

Default to [starting questions](starting-questions.md) and work inside the agreed scope. No `PLAN.md` or extra “go” is required.

Show/create a plan only when requested: goal, quality, baseline, experiments, estimated cost, deadline and deliverables. Wait only for a requested checkpoint or genuinely new scope/spending authorization.

Dry-check intake before `--run-dir`; record authorization source/time/scope in `state.decisions`. Reuse existing session and intake approval. Shorter remaining time does not revoke it: adjust experiments and record omissions. Budget expansion or deadline extension needs permission.

On resume, accept legacy `PLAN.md`/`Approved:` evidence; never require that file for new runs. `plan: skip` remains harmless. A changed pinned policy needs a new run with prior evidence preserved.

Respect an already active client plan mode, but never enter it automatically. Client permission prompts are separate from plugin planning.
